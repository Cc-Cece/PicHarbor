### 讨论结论（安装方式 / 交付形态）——已对齐，仍未写代码
- 交付形态：**单文件便携 exe**。用户只拿一个 `PicHarbor.exe`，双击即用。不启用锁 = 纯便携（无服务/无注册表/无 UAC）。
- 启用锁时：**同一个 exe 带内部参数 `--vault-service` 把自己注册为 LocalSystem 服务**（不额外分发第二个文件），弹一次 UAC，用完即弃，日常 GUI 不提权。
- 决策：关闭锁后**服务保留空转**（不注销）；设置页提供「**彻底移除应用锁组件**」按钮（注销服务 + 删 `%ProgramData%\PicHarbor`）。
- TOTP 定位：**不是第二种解锁方式**，只是「忘记密码后重置密码」的验证手段；重置成功 ≠ 解锁，目录仍锁着，要用新密码再解锁。
- 一次性恢复码：**第一版不做**。重绑授权：**当前应用密码 + 当前 TOTP 码双验证**。

## 修复：「点击启动服务立刻停止」+「服务在跑但客户端连不上」（本次，关键）

用户报障：点启用→装服务后服务立刻停止（截图两张）。逐层定位到 **4 个真实缺陷**：

### 缺陷 1：管道层 ACL 需要特权，直接拖垮服务
`PipeServer` 里 `pipe.SetAccessControl(pipeSec)`（写 DACL/改所有者）需要 `SeSecurityPrivilege`/`SeTakeOwnershipPrivilege`，服务令牌里这两个特权存在但**未启用** → 抛 `UnauthorizedAccessException`。
因 `BackgroundService` 默认 `BackgroundServiceExceptionBehavior.StopHost`，一个 accept 循环异常就把整个 Host 干掉 = **服务立刻停止**。
**修复**：彻底删除管道层 ACL（权限边界收到命令层 `IsAuthorizedIdentity` / `IsDailyCommand`）；`Program.cs` 与 GUI 宿主都设 `BackgroundServiceExceptionBehavior.Ignore`；`RevokeAllOnStartup` 包 try/catch；accept 循环加退避重试。

### 缺陷 2（最隐蔽）：先模拟后读 → RunAsClient 必抛 IOException
`HandleConnectionAsync` 原来**先** `pipe.RunAsClient(...)` **再** `reader.ReadLineAsync()`。
Win32 `ImpersonateNamedPipeClient` 硬性要求「服务端**已先从管道读取过数据**」，否则返回 `ERROR_CANNOT_IMPERSONATE (1368)`，.NET 抛
`IOException: 无法在该管道上模拟`（英文 "Cannot impersonate..."）。
当时 `catch { logWarning; return; }` 直接 return —— **从不写响应**，客户端只看到 `Connect` 超时。
症状极具误导性：服务进程活着、日志有 "waiting for connection"、管道枚举得到、`WaitNamedPipe` 成功，但任何命令都超时。
**修复**：把顺序改成「先 `ReadLineAsync` → 再 `RunAsClient`」。身份与管理员判定在同一次模拟里一并取出（`IsAuthorizedIdentity`），避免二次模拟。

### 缺陷 3：命令处理异常逃逸 → 客户端只看到 ERROR_BROKEN_PIPE (109)
任何 handler 抛异常都会穿透 `HandleConnectionAsync`，`await using (pipe)` 在写响应前释放管道 → 客户端收到断管（err 109），**且服务端不记录任何错误**。
**修复**：`switch` 外再包 try/catch，异常一律转成 `{ok:false,error:"Internal error."}` 响应并 `LogError`。

### 缺陷 4：非提权写受保护目录抛异常
`VaultStore.EnsureDirectory()` 调 `HardenDirectory`（读/改 ACL 需管理员）→ 非提权时抛 `UnauthorizedAccessException`，且未被容错包裹。真实触发场景是「当前用户的 `%ProgramData%\PicHarbor` 已被历史运行锁成 SYSTEM-only」。
**修复**：`EnsureDirectory` 硬化包 try/catch（失败只告警，下次以 SYSTEM 启动会再收紧）；`VaultState.TrySetPassword/TryChangePassword/TryResetPasswordWithTotp` 捕获 `UnauthorizedAccessException` 并返回可读错误。

## 修复（第 2 轮）：「服务已安装但未能连接」= 管道 DACL 拒绝交互式用户

用户重启服务后反馈：服务 Status=Running，但仍提示「服务已安装但未能连接」。

### 定位过程（关键）
1. 查服务：`PicHarborVault` Running，pid 20180，LocalSystem，binPath 指向仓库 Release。
2. **管道已存在**：`\\.\pipe\PicHarborVault` 在 `GetFiles("\\.\pipe\")` 里能枚举到。
3. 原生探测：`WaitNamedPipe` **成功(1)**，但 `CreateFileW` 返回 **err 5 = ERROR_ACCESS_DENIED**。
