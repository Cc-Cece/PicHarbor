# Release notes — v1.1.0

**Release date:** 2026-07-04
**Tag:** `v1.1.0`

## Highlights

The first **feature** release since v1.0 — the archive is now easier to browse and to search, and you can
restructure an existing one safely. The default folder layout is now a **flat `YYYY-MM`**, a new
**`search`** command finds media without the iPhone, and a new **`reorganize`** command migrates an existing
archive between layouts entirely offline. **Existing archives are never touched on upgrade** — each archive
remembers the layout it was created with.

## What's new

- **Flat `YYYY-MM` is the new default layout.** New archives organize as `YYYY-MM\IMG_0001.HEIC` (one click
  to any month) instead of the nested `YYYY\YYYY-MM\`. The layout is **recorded per archive** on the first
  copy and always wins on later runs, so **upgrading never re-shuffles or re-copies** an existing archive. (#65)
- **`copy --organize-by {month | year-month | year | flat}`** — choose the folder layout when you create an
  archive. `month` (flat `YYYY-MM`) is the new default; `year-month` is the previous nested layout, still
  available; `year` and `flat` are also offered. A later run with a conflicting value **warns and keeps** the
  recorded layout. (#65)
- **`search` — find media without the iPhone** (read-only). Query an archive's manifest by date range, media
  type, size, camera, or GPS-present; it prints a table, and `--open` reveals the matching folders in
  Explorer. No device connection is made. (#65)
- **`reorganize` — restructure an existing archive, offline.** Migrate an archive between layouts by moving
  files on the PC (the iPhone is never involved). Every move is a same-volume **atomic rename**, and the run
  is **resumable and crash-safe** — an interrupted `reorganize` heals on the next run without losing or
  duplicating a file. `--dry-run` previews the moves first. (#68)

## Fixes

- No user-facing bug fixes — v1.1.0 is purely additive. The most recent security patch shipped in
  [v1.0.1](v1.0.1.md) (SQLite CVE-2025-6965).

## Known limitations

Unchanged from v1.0 (see the README's "What this tool does NOT do"), plus a couple of notes for the new
commands:

- Copies only what is physically on the device's `/DCIM/`. iCloud-only items and "Optimize iPhone Storage"
  placeholders that haven't been downloaded to the device cannot be copied.
- Windows (win-x64) only; USB (AFC) only — no Wi-Fi transfer.
- `reorganize` restructures **within a single archive root** — it does not move an archive to a different
  drive, and it is a separate, explicit command (a normal `copy` never re-shuffles an existing archive).
- `search` date filters are evaluated in UTC; a file dated only by its modified-time (no EXIF) can fall a day
  either side of a local-timezone boundary.

## Safety

- The **read-only device contract still holds** — `get-and-see` never writes to, deletes from, or renames
  anything on the iPhone (enforced by `ReadOnlyContractTests`). Both new commands, `search` and
  `reorganize`, make **zero** device calls — they are entirely offline.
- **`reorganize` is integrity-first:** same-volume atomic renames, never an overwrite, with a crash-reconcile
  that heals an interrupted move. QA verified **byte-identity (SHA-256)** across full layout round-trips and a
  worst-case hard-kill mid-run on a 32,000-file archive — zero files lost, corrupted, or duplicated.
- The shipped single-file EXE is verified by CI to contain **no test-only fake-device code**.

## Upgrading

A drop-in replacement for v1.0.x. Existing archives and journals are fully compatible: the journal
**auto-migrates (v2 → v3, additive)** on first use and **keeps your current folder layout** — no re-copy, no
re-shuffle. If you want to switch an existing archive to the new flat `YYYY-MM` layout, run the new
`reorganize` command (try `--dry-run` first).
