# Release notes — v1.0.0

**Release date:** _pending QA Stage 2 (#21) sign-off — the `v1.0.0` tag is cut only after the full
hardware acceptance run passes._
**Tag:** `v1.0.0`

The first public release of **get-and-see** — a single-file, **read-only** Windows CLI that copies your
entire iPhone camera roll to a PC over USB (Apple's native AFC protocol), built to move a worst-case
~400 GB / ~38k-file library reliably and resumably.

## Highlights

- **Copies your whole `/DCIM/`** — photos, videos, Live Photos, screenshots, screen recordings — with
  original EXIF preserved, organized into `YYYY/YYYY-MM/` date folders.
- **Read-only by architectural design.** The iPhone is never written to or deleted from; a build-failing
  test enforces it.
- **Reliable at scale:** atomic per-file writes, size verification, a SQLite journal that makes the whole
  transfer resumable, and a read-stall watchdog that stops cleanly on a cable yank or sleep.
- **A queryable manifest** (`get-and-see.db`) and a human-readable `summary.txt` at the destination root.

## What's in v1.0 (Sprints 1–3)

**Core copy pipeline (Sprint 1)**

- Read-only AFC client over `imobiledevice-net`; `/DCIM/` enumeration; EXIF date-organization
  (`YYYY/YYYY-MM/`, `unsorted/` for undated files).
- Atomic copy: stream → staging `.partial` → `fsync` → **size-verify** → atomic rename. Never publishes a
  partial or size-mismatched file.
- SQLite journal + `manifest` view at `<dest>/get-and-see.db`; journal-aware **resume** (done files
  skipped, pending/failed retried). Filename collisions disambiguated (`_2`, `_3`, …) — never overwritten.
- Pre-flight checks: driver service reachable, destination writable, sufficient free space (+5% headroom).
- `summary.txt` regenerated every run.

**UX, resumability & pre-flight (Sprint 2)**

- **Read-stall watchdog** (`--read-timeout`, default 30s) → clean, resumable stop (exit 3) instead of an
  indefinite hang.
- **Live dashboard** (Spectre.Console): current/average speed, ETA, counts; graceful text fallback and
  `--no-dashboard`. Adds no measurable slowdown.
- `status --dest` subcommand (archive totals + last run, **no device needed**); `runs`/`devices` history;
  on-battery pre-flight warning; Live-Photo pair detection in the summary.

**Hardening, packaging & docs (Sprint 3)**

- **Long-path support** — destinations beyond the legacy 260-character limit work transparently (`\\?\`).
- **`--verify-hash`** — opt-in SHA-256 computed during the copy and recorded in the manifest's `sha256`
  column. Read-only; off by default with zero cost.
- **Single-file release pipeline** — `v*` tag → self-contained win-x64 `get-and-see.exe` + `.sha256`
  attached to a GitHub Release; the published EXE is smoke-tested (`--help`) before it's trusted.
- **CI gates:** published-EXE smoke test and a gitleaks secret scan.
- Full user docs: this README, [troubleshooting](../user/troubleshooting.md), and the
  [manifest schema](../user/manifest-schema.md).

## Known limitations

- **Apple Photos organization is not preserved** — albums, keywords, favorites, People/Face tags, iCloud
  Shared Albums, and Memories live in Apple's internal database, not in `/DCIM/`. See the README's
  "What this tool does NOT do". You get a complete, faithful copy at the **raw-file** level.
- **Windows x64 only.** Requires the Apple Mobile Device USB driver (iTunes **or** the "Apple Devices"
  Store app) and a one-time "Trust This Computer".
- **Throughput is link-bound** (~30 MB/s over the iPhone 12 Pro USB-2.0 Lightning port) — a full ~270 GB
  library takes a few hours. Disable PC sleep and stay on AC power.
- **`--verify-hash` records** a SHA-256 during copy; a standalone **verify-only re-check** of an existing
  archive is planned for a fast-follow release.
- Aging native dependencies in `imobiledevice-net` (local-USB-only, read-only, no network → minimal
  exposure) are accepted for v1.

## Safety

The read-only device contract holds: no AFC/lockdown write, delete, rename, truncate, or mkdir symbol is
referenced anywhere in the code, enforced at build time by `ReadOnlyContractTests`. There is no CLI flag
that mutates the device. No network, no telemetry — local USB only.

## Install & verify

Download `get-and-see.exe` from the release and verify it:

```pwsh
(Get-FileHash .\get-and-see.exe -Algorithm SHA256).Hash
# compare to get-and-see.exe.sha256 attached to the release
```

No install, no admin rights, no .NET runtime required (single self-contained win-x64 file).
