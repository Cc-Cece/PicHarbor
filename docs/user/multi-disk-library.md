# 多盘图库、备份安全与恢复

PicHarbor 使用一个逻辑图库管理多个归档目录。成员各自保存照片原文件和 `.picharbor`
索引；界面的浏览、搜索和统计合并显示。存储位置保留在每个媒体记录中。

## 切盘继续备份

在设置中更换备份磁盘时，新建归档目录会加入当前图库。D 盘已有照片留在 D 盘，
后续照片写入 E 盘。目标目录如果已有独立图库，先单独展示；使用“纳入当前图库”明确合并。

D 盘离线时，离线记录不能证明照片安全，因此照片允许重新备份到 E 盘。离线照片继续
展示位置不可用，打开和上传时不会静默取用另一张照片。盘重连后自动自检。

复制整个归档目录可能复制成员身份。原目录和复制目录同时在线时，复制库可以查看，
但自检拒绝自动清理；主动纳入后，它才获得新的成员身份。搬动归档时保留全部原文件及
`.picharbor`，通过新目录打开以重新定位成员。丢失本机缓存可以从成员目录重建索引。

## 增量判断和严格校验

每次首次复制都在流式写入过程中记录 SHA-256，并在发布原文件前核对大小和落盘。
快速模式按设备身份、源路径、大小和修改时间判断，再验证在线归档副本；不同设备不能
仅凭路径和大小互相跳过。设置中的严格校验还会重新读取手机文件比较内容。

文件由暂存区发布成功后才写完成记录。若设备断开或任务取消，暂存文件不会被当成原图。
FTP 的协议和兼容方式保持不变；网络传输本身没有新增加密协议。

## 自检、重复副本和恢复

应用启动、成员重连、备份完成会触发自检，设置里也提供手动入口和取消按钮。
只处理软件已登记的原文件；不扫描整块磁盘，不对外部上传目录、`.AppleSync`、缓存、
暂存、回收区和未知文件自动去重。

大小及 SHA-256 完全一致才属于同一内容。相似照片、编辑版、Live Photo 的不同组件
分别保留。自检识别归档内部的改名/移动，更新位置和关联；发现修改后的内容时保留版本，
并报告旧内容已变化。

重复实体优先保留已验证的主副本，随后按磁盘类型、首次归档时间及稳定身份决定。
多余实体移动到原成员的 `.picharbor/recycle`，默认保留 30 天。到期时再次核验在线保留
副本及回收文件；保留副本离线、不可访问或核验失败就延期，不删除最后一份可用照片。
操作先写恢复记录，移动中断后下次自检继续恢复。

在设置中刷新可恢复副本，选择条目并恢复。恢复副本不会立即被下一轮自检重复回收。
回收的副本不算用户删除，也不会触发重新备份。

## 删除电脑副本后

“删除电脑副本后重新从设备备份”默认开启。只有成员在线、可访问，并确认没有有效
归档副本时才认定用户删除。第一次实际遇到时询问一次，选择立即生效并保存；取消
询问不会消耗这次提示。以后可以在设置修改。

关闭重新备份会保存设备源身份的排除记录，不删除或修改手机原图。重新开启后允许
重新备份。离线、权限错误和软件自动回收不会触发删除询问。该设置属于当前 Windows
用户；换电脑后默认重新备份。

## 整理与多电脑使用

整理在各成员盘原地执行，保留媒体身份、历史和手动选择。离线成员的整理会排队，
下次重连自检继续执行；未完成整理的写入成员先完成自检再备份。跨盘同名但不同内容
的照片导出到手机目录时使用稳定后缀，避免互相覆盖，并保留 Live Photo 组件的同名配对。

同一在线成员目录使用跨进程写锁。其他实例可以查看，不能并发备份、整理或清理。
换电脑前结束旧电脑任务并安全退出；检测到其他电脑中断的写入会暂停修改。
确认旧电脑已停止写入、所有成员在线后，才能使用“恢复图库写入”。此版本不支持两台
电脑各持断开的成员盘，同时修改同一个图库，也没有云端写入协调。

## 应用锁与隐私范围

应用锁使用 Windows 权限保护登记目录，服务重启会重新收回目录及子项权限。
锁定/解锁失败会报告受影响目录，不能当作成功。首次设置和安装服务经过提权，后续
目录登记要求授权会话和目录管理权限。服务镜像和凭证存储使用受保护目录，服务端
识别 Windows 用户并校验应用密码；协议不兼容或无法确认保护状态时暂停受保护操作。

FTP 和 Google 凭证使用当前 Windows 用户的 DPAPI 保存，旧明文配置在读取时原子
迁移。缩略图和本机离线索引加密保存，锁定时清除内存预览并停止提供媒体。
管理员、离线读取硬盘及外部程序已有的文件句柄不在日常隐私保护保证内；原图仍是
普通照片文件，此功能没有建设加密保险库。

照片较多时，锁定或解锁需要等待目录权限应用完成。期间可查询服务状态，界面显示
正在处理；完成之前不会报告解锁成功。解锁后的再次验证不会重复扫描整个图库。
通信超时会显示实际等待时长，不会被误报为密码错误。

## CLI 示例

```powershell
picharbor library include --dest "D:\Photos" --member "E:\Photos"
picharbor library check --dest "E:\Photos"
picharbor library recycled --dest "E:\Photos"
picharbor library restore --dest "E:\Photos" --operation "列出的操作ID"
picharbor library reclaim-writer --dest "E:\Photos"
picharbor copy --dest "E:\Photos" --strict-verify
picharbor status --dest "E:\Photos"
```

CLI 第一次遇到删除时会在交互终端询问。输入被重定向时沿用当前安全默认值，且不记为
已经询问。`--verify-hash` 保留兼容，所有新复制本来就会记录哈希。

## 升级与故障处理

v8 升级前通过 SQLite 一致性备份保留 `.pre-v8`，结构迁移在事务内验证再提交。
旧根目录数据库搬入 `.picharbor` 采用备份、验证和发布流程，保留原数据库作为恢复
依据，不能逐个移动正在使用的 DB/WAL/SHM。不要手动降低数据库版本号或用旧程序写库。

出现身份冲突、权限故障或迁移失败时保留原文件及整个 `.picharbor`，先修复定位或权限。
不要凭文件日期猜测哪份数据库有效，也不要删除回收区来掩盖故障。未知历史关系保留
在迁移审查记录中，不作为新设备跳过备份的依据。
